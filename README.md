# Школьный дневник (MVP)

Минимальная версия приложения: **загрузочный (boot) экран + вход и регистрация через Supabase**.
Стек: Vite + React 18 + `@supabase/supabase-js`. Никаких лишних зависимостей — вся авторизация
работает на встроенном Supabase Auth.

## Быстрый старт

Нужен Node.js 20+.

```powershell
npm install
# .env уже создан; если его нет — скопируйте .env.example в .env
npm run check:auth   # проверка ключа и связи с Supabase
npm run dev          # откроется http://localhost:5173
```

### Переменные окружения (`.env`)

```ini
VITE_SUPABASE_URL=https://<ваш-проект>.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_xxxxx
```

* `VITE_SUPABASE_ANON_KEY` — **публичный** ключ (Publishable key или legacy `anon`).
  Он попадает в JS-бандл, это нормально: доступ к данным ограничивают правила RLS.
* Ключи со словом `secret` и `service_role` в приложение класть **нельзя** — они полностью
  обходят RLS. Файл `.env` добавлен в `.gitignore`.
* Откуда взять: Supabase → **Project Settings → API Keys**.
* `VITE_SUPABASE_URL` — именно база проекта, без `/rest/v1/`.

## Что проверить вручную

1. Открыть `http://localhost:5173` — появляется загрузочный экран, затем форма входа.
2. Вкладка **Регистрация**: указать имя, email, пароль (мин. 6 символов), выбрать «Ученик/Родитель» → «Создать аккаунт».
3. Если в Supabase включено подтверждение email (по умолчанию), появится сообщение «Аккаунт создан. Мы отправили письмо…».
   Пользователь появится в **Authentication → Users** (в статусе «не подтверждён»).
   Для тестов можно отключить подтверждение: **Authentication → Sign In / Providers → Email → Confirm email** (выключить) — тогда после регистрации вход происходит сразу.
4. Войти с созданным аккаунтом: появляется экран с приветствием, ролью и кнопкой «Выйти».
5. Обновить страницу — сессия сохраняется, загрузочный экран ведёт сразу в дневник.
6. Проверить ошибки: неверный пароль → «Неверный email или пароль»; занятый email → «Пользователь с таким email уже зарегистрирован».

## Как это работает

* `AuthProvider` при старте вызывает `supabase.auth.getSession()`, подтягивает профиль и только потом
  скрывает загрузочный экран (минимум 1.4 с, чтобы он не «мигал»). Дальше `onAuthStateChange`
  автоматически переключает экраны при входе/выходе.
* Регистрация кладёт имя и роль в метаданные пользователя (`user_metadata.full_name`, `user_metadata.role`).
  Когда будет применена SQL-схема, триггер `handle_new_user()` создаст запись в таблице `profiles`
  автоматически — приложение начнёт читать `full_name` и `role` из неё.
* Если таблицы `profiles` ещё нет, вход всё равно работает: данные берутся из метаданных Auth,
  а на экране дневника показывается информационное сообщение (`src/context/AuthContext.jsx`).

## Безопасность — сделать сразу

В переписке появлялись **секретные** ключи проекта (`service_role` JWT и `sb_secret_...`).
Их нужно считать скомпрометированными и перевыпустить:

1. Supabase → **Project Settings → API Keys** → перевыпустить (`Rotate`) **Secret key**.
2. Там же перевыпустить и JWT-секрет (кнопка `JWT Secret` → `Rotate`), если использовался legacy `service_role`.
3. Убедиться, что в коде и в `.env` лежит только публичный ключ (`sb_publishable_...` / `anon`).
4. Никогда не вставлять секретные ключи в чаты, скриншоты и репозиторий.

Файл `.env` в `.gitignore` и в репозиторий не попадёт — в git хранится только `.env.example`.

## Если что-то не работает

| Симптом | Что делать |
| --- | --- |
| `Не заданы VITE_SUPABASE_URL или VITE_SUPABASE_ANON_KEY` | создайте `.env` из `.env.example`, после правки `.env` перезапустите `npm run dev` |
| «Нет связи с Supabase» | проверьте интернет, правильность URL, что проект не на паузе (Supabase → Project → Restore) |
| «Регистрация отключена…» | Authentication → Sign In / Providers → Email → включить `Enable email provider` |
| Письмо с подтверждением не приходит | для локальных тестов отключите `Confirm email`, либо смотрите письма в Supabase → Authentication → Users |
| Пароль отвергается при регистрации | минимум 6 символов (или больше, если изменена политика в Authentication → Policies) |
| `npm run check:auth` даёт FAIL по ключу | скопируйте актуальный Publishable/anon ключ из Project Settings → API Keys |
